# Google Finance Earnings

## Purpose and entry point

使用 Codex 內建瀏覽器處理 Google 財經 Beta 版的財報與基本面讀取。從目前已開啟的 Google 財經分頁開始；首頁可由 `更多即將發布的財報` 進入財報行事曆，個別公司可由搜尋建議或行事曆的公司連結進入報價頁。

## Procedure

1. 先核對目前分頁 URL、標題、登入變體與頁面是否完成載入。等待 `progressbar` 消失後再判斷財報行事曆是空結果還是仍在載入。
2. 查行事曆時開啟 `更多即將發布的財報`，使用 `昨天`、`今天`、`明天`、`本週`、`下週`，再用 combobox 的 `所有股票` 或已登入變體的 `在你的清單中` 篩選。核對選取的日期 tab、篩選值與清單中的公司連結。
3. 查單一公司的收益時，先透過搜尋選取明確的交易所版本，或從行事曆公司連結進入 quote 頁，再選取 `收益`。讀取上一份報表日期、會計期間、每股盈餘／預估值、收益／預估值、超出或未達預期，以及法人說明會錄音、轉錄稿與精選內容。
4. 查財務報表時選取 `財務`，再依需求選 `損益表`、`資產負債表` 或 `現金流量`。先記錄頁面顯示的單位與期間控制，再讀取表格欄位；不要把當次的數值寫入 reusable guidance。
5. 查持有資產時選取 `持有資產`，再選 `內部人士` 或 `政治人物`。記錄表格欄位、第三方資料標示、目前頁碼與分頁狀態；必要時使用 `下一頁`，每次都核對表格標題與頁碼。
6. 回報結果時附上標的代號／交易所、頁籤、期間、單位、資料來源標示、目前 URL 與抓取時間；將 AI 摘要、第三方資料與原始表格分開描述。

## Page and field semantics

- `收益` 是公司財報摘要與法人說明會資料，可能包含音訊播放器、轉錄稿與精選內容。
- `財務` 將報表按損益表、資產負債表、現金流量分組；所有值以頁面顯示的公司／市場貨幣呈現，必須以當次頁面為準。
- `持有資產` 在探索到的頁面中提供內部人士交易與政治人物持有資產兩類，頁面明示資料由第三方提供。
- `財報行事曆` 的公司卡片提供日期、時間、會計期間、預估每股盈餘與預估收益；`新增至日曆` 是外部 Google Calendar 連結，不要在未獲要求時點擊。

## Safety and limits

- 只做讀取、切換 tab、開啟下拉選單與分頁。不要播放音訊、送出研究問題、建立工作、建立投資組合、加入清單或開啟外部日曆，除非使用者明確要求並確認可能的外部／帳戶效果。
- 行事曆、EPS、收益、分析師估計、財務數字與交易紀錄會變動；不要引用舊畫面或硬編碼本次數值。
- AI 摘要與第三方交易／持有資料需要標示其來源；不要把網站摘要當成公司原始申報或投資建議。

## Drift maintenance

- 操作前比較目前可見 UI 的頁籤、欄位、期間控制、資料來源標示與權限。
- 若 UI 改變，以目前 UI 完成最小安全讀取，並記錄公開／已登入變體、頁型、舊行為、新行為、驗證訊號與日期。
- 只有差異穩定且可直接由 UI 驗證時，才更新負責的 `AGENTS.md`、skill 或 reference；不記錄動態結果、個人資料、cookies 或 tokens。
- 更新後重跑受影響的行事曆／公司頁流程與 `quick_validate.py`。
