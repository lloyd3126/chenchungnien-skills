# Evidence discipline for Manny Pro research

Read this reference before applying any method in this skill. It defines how to preserve the boundary between what an article says, what an underlying source shows, what the researcher calculates, and what is still unknown.

## Choose the source mode

Record one mode at the start of the work:

1. **Source-bound mode**: use only the local article archive, local series notes, and other files the user placed in scope. Do not browse or imply that an article-era fact is current. If a current price, law, KPI, or company status is absent, mark it `current status unverified`.
2. **Current-state mode**: recheck time-sensitive claims against dated first-party or authoritative sources. Preserve the article-era observation beside the current observation so that changes remain visible.

An explicit user instruction not to use the internet always selects source-bound mode.

## Label source and status separately

Use one **source type** and one **verification status** for each material claim.

| Source type | Meaning |
|---|---|
| Article observation | The local article or series note states the claim |
| Underlying source in article | The article attributes the claim to a filing, interview, study, regulation, or dataset that has not necessarily been reopened |
| Archived first-party disclosure | A locally saved filing, presentation, transcript, or company document directly supports the claim |
| Researcher calculation | A reproducible result derived from listed inputs |
| Researcher inference | An interpretation connecting observations; not directly stated by a source |
| Assumption/proxy | An input used because the required fact is unavailable |
| Unknown | Evidence is missing or contradictory |

Use these statuses: `directly checked`, `article-derived`, `calculated`, `inferred`, `assumed`, `conflicted`, or `unverified`.

Do not label an article quotation or summary as a directly checked company fact unless the underlying document was actually opened. Do not upgrade repeated claims into independent confirmation when they trace to the same source.

## Maintain a claim ledger

For every thesis-changing claim, record:

| Claim | Source type | File/source and date | Period covered | Status | Calculation/assumption | Falsifier | Freshness need |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |

- Cite the local file and section when working from the archive or series notes.
- Preserve the original reporting period, currency, geography, segment, and denominator.
- If two sources conflict, keep both values, explain the definitional difference if known, and do not average them by default.
- Distinguish `0`, `not disclosed`, `not found`, and `not applicable`.

## Calculation rules

- Show formulas, units, input periods, normalizations, and residuals.
- Reconcile bottom-up calculations to reported totals when possible; leave unexplained residuals visible.
- Use ranges for proxies and assumptions. Do not manufacture precision to fill a missing input.
- Keep management guidance separate from realized results and state the conditions required for the guidance.
- A model output is not an observed fact, even if the formula is exact.

## Freshness and offline limits

Price, valuation, law, licenses, management, product terms, market share, and operating KPIs are time-sensitive. In source-bound mode:

- state the newest local observation date;
- describe conclusions as article-era or archive-era conclusions;
- do not give a current valuation conclusion without a dated local or user-provided price;
- do not describe a regulation as current law unless a locally stored current official source supports it;
- turn missing current facts into a verification queue, not an invented answer.

## Minimum output

Every completed method application must include the source mode, claim ledger, formulas and assumptions, unresolved conflicts, freshness limitations, and at least one observable falsifier for each core thesis.
