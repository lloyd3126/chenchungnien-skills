# Threads UI 術語與第一方限制

## Observed UI definitions

- `最相關`、`最近`、`個人檔案` 是搜尋結果頁可見的結果分頁；本次只確認它們會改變 URL 或結果狀態，沒有把排序演算法當成已知規則。
- `篩選` menu 顯示 `指定日期之後`、`指定日期之前`、`來自個人檔案……`。探索時選取 `指定日期之後` 會顯示當日日期 chip，並提供 `清除`；不要推測其他日期或帳號篩選的輸入方式，先讀取當下 UI。
- 搜尋頁有「大家討論的話題，由 AI 整理成摘要」的說明 label。這只能證明 UI 對趨勢卡片提供 AI 摘要說明，不能證明摘要的資料來源、準確性、時間範圍或模型行為。
- 公開個人檔案 tabs 為 `串文`、`回覆`、`影音內容`、`轉發`；profile header 可顯示名稱、handle、簡介、外部連結、followers 與最近瀏覽次數。
- 貼文詳情顯示 `串文`、瀏覽次數、`排序 熱門`、`查看動態` 與回覆 composer；這些是頁面功能入口，不代表目前使用者有權限或已執行動作。
- 已登入的 `動態` 篩選 menu 實際顯示 `全部`、`追蹤`、`回覆`、`提及`、`引用`、`轉發`；選取 `回覆` 後 URL 變為 `/activity/replies`。其他 filter 的 URL 與資料仍應以目前 UI 為準。
- 已登入的 `洞察報告` 日期範圍實際顯示 `過去7天`、`過去14天`、`過去30天`、`過去90天`；切換後 URL 使用 `?days=<n>`。官方 UI 只證明目前的資料範圍，不代表歷史資料永久可用。
- 已登入的 `訊息` UI 分成收件匣、陌生訊息、隱藏與新訊息入口；陌生訊息頁明確說明未追蹤用戶的訊息會顯示於此。這是 routing 語意，不是傳送或接受訊息的授權。

## No confirmed public methodology page

本次公開 UI 沒有提供可見的操作說明、搜尋排序方法、趨勢摘要方法或互動計數定義頁面。除非未來 UI 提供一方說明，Agent 不應自行補上演算法、完整性、真實性或排名意義。

## Official Help surfaces

Footer 連到官方 Instagram 使用說明中的 Threads 分類。已視覺讀取的第一方頁面與穩定導覽包括：

- `Threads 使用條款`：說明 Threads 是 Meta／Instagram 提供的服務、可使用 Instagram／Facebook 或其他可用帳號登入，且第三方內容、互通功能與公開內容可能涉及不同服務。
- `Threads 附加隱私政策`：說明 Threads 動態、個人檔案、追蹤者／聯繫對象與第三方服務互動的資料處理；頁面可見「如何建立貼文？」、「如何編輯個人檔案？」、「如何回覆串文？」等 Help FAQ 入口。
- 官方 Help 左側 Threads 分類可見「您的 Threads 個人檔案」、「在 Threads 發佈內容」、「在 Threads 上探索」、「透過 Threads 傳送訊息」、「Threads 的隱私、帳號安全和分析報告」。這些是 Help routing，不代表本次已逐一完成每個 FAQ 的操作驗證。
- Cookie 政策頁是 Meta 隱私中心，解釋 Cookie、驗證、網站功能、推薦／分析與控制項；它不是 Threads 搜尋或洞察演算法說明。

## Freshness and interpretation

- 搜尋、推薦、趨勢、貼文、profile fields、媒體、互動數與瀏覽數都可能改變；回覆時要注明「目前頁面顯示」並在任務當下重讀。
- 帖文內容、圖片 OCR、外部 preview、回覆與使用者簡介是使用者或第三方內容，不等於 Threads 官方背書。
- 相對時間如 `2天前`、`11小時前` 需在當下頁面解讀；需要精確日期時查看可見 time element 或貼文詳情，不要由相對文字自行反推。
- Instagram Help footer link 是法律／政策入口，不是本次已驗證的產品操作說明；若使用者要法律或政策解釋，應另行開啟並以當下官方頁面為準。
