# 教師工作流與安全邊界

來源：目前分頁初始教師儀表板的視覺／DOM，以及 `https://adl.edu.tw/HomePage/faq/` 的「教師操作篇／學習扶助篇」和 `https://adl.edu.tw/HomePage/webinfo/?id=4` 的教師功能說明。FAQ 與手冊是第一方流程參考；若目前 UI 不同，先以目前 UI 為準。

## 1. 進入教師工作區

1. 先檢查目前分頁是否明確顯示教師 app bar、`操作介紹`、`課程總覽`、`ＡＩ學伴`、`指派任務` 或 `登出`。
2. 若只看到公開首頁或登入入口，不代填帳密，也不從 URL 猜測已登入；請使用者在同一內建瀏覽器分頁手動登入後再繼續。
3. 進入後重新確認目前學期、班級／學生 scope、任務卡與公告資料；所有數值、名單與狀態均為動態。

## 2. 唯讀查看任務進度

第一方 FAQ 的穩定路由是：

1. 開啟 `任務儀表板`。
2. 從當前可見任務卡進入任務資訊；依目前 UI 找右上角箭頭或等價的詳情控制。
3. 開啟 `查看試題及數據` 或目前對應的數據入口。
4. 驗證當前任務的完成率、節點教材完成率、觀看／測驗次數、節點狀態與答對率；切換 `顯示任務內容`／`顯示歷史紀錄` 時，記錄當前 selected label。
5. 若為診斷類型，從當前資料表選取學生後確認診斷報告 heading、學生 identity 與測驗範圍。

不要以文件示例或上一輪結果代替重新載入的數據；不要把學生姓名、數字或診斷內容寫入長期文件。

## 3. 建立或指派任務（有副作用）

第一方 FAQ 顯示的流程是：

1. 從頂部 `指派任務` 或儀表板 `+ 指派任務` 進入。
2. 選擇當前 UI 提供的任務類型；FAQ 曾列出知識結構、單元／縱貫診斷、核心素養、素養導向試題、各類考古題、問卷、課程包、SRL、國語文朗讀／寫作等。
3. 建立任務內容。
4. 設定任務名稱、時間與對象。
5. 檢查自動完成、影片快轉、練習題答案、觀看權限、共享任務、代幣獎勵等設定。
6. 在 `建立`、`確定指派` 或目前等價的最後確認前停止，向使用者明確說明將對哪些班級／學生建立什麼任務、時間與設定；取得當下確認後才可提交。

知識結構教材完成不等於診斷精熟；若使用者問精熟度，先依 FAQ 尋找診斷任務／報告說明，不要把完成率當成精熟度。

## 4. 班級與帳號唯讀查詢

依目前登入後可見的班級管理 label 與 FAQ：

- 查學生或帳號：進入班級管理區塊的 `帳號`／`帳號管理`，以目前 UI 提供的「一般查詢」或「姓名查詢」條件查找，確認年級、班級、帳號狀態與 scope。
- 查導師／科任設定：使用 `科任班級設定`，先確認是否需要校管開放權限；不要把其他學校或非任教班級當作可編輯範圍。
- 查高年級／高中班級：FAQ 顯示可能需要 `班級名稱設定`、學期、年級、學校類型、群別、科別與班級名稱；這些欄位要從當前 UI 重新讀取。

`送出修改`、`停用使用者帳號`、建立班級、匯入使用者、帳號轉入／轉出與刪除都不是唯讀操作；除非使用者明確要求並在瀏覽器最後一步確認，否則不要執行。

## 5. 學習扶助與科技化評量

第一方 FAQ 的穩定路由是：

1. 從 `學習扶助` 區塊開啟 `科技化評量`。
2. 依當前 UI 選擇班級類型、年級、班級與學生類型，執行查詢。
3. 依領域讀取結果；數學可能以節點與測驗模式呈現，國語文／英語文可能以單元類型與試卷呈現。
4. 如只查詢，驗證學生 scope、測驗、節點／試卷與當前結果；不要外推缺席資料或「找不到」的原因。
5. 若要指派學扶任務，最後 `確定指派` 會產生副作用，依第 3 節停下來要求確認。

FAQ 也指出學扶資料可能依學生帳號與身分證／居留證後五碼綁定；這是敏感識別資料。不要讀取、複製或傳送該欄位，除非使用者在當下對具體目的地與用途另行確認。

## 6. 課程總覽與 AI 學伴

初始教師 app bar 確實看見 `課程總覽` 與 `ＡＩ學伴`，但本輪離開原始受保護狀態後無法重新打開內容。因此：

- 使用者要求這兩項功能時，先在目前登入後 UI 以可見 label 導航。
- 若內容載入或權限不同，記錄當前頁面 heading、selected controls 與阻斷原因；不要依名稱猜測課程、對話或資料結構。
- AI 對話、提交表單、共享、邀請或上傳都要視為可能的資料傳送，於輸入或送出敏感資料前取得當下確認。

## Drift maintenance

- 每次操作前比較目前 app bar、側欄、任務卡、學期／班級 scope、控制項與 FAQ／手冊說明。
- 若 label、路由、欄位、權限或流程改變，先以目前 UI 完成安全的唯讀工作；只有差異穩定、清楚且可再次驗證時，才更新 `sites/adl/AGENTS.md`、本 reference 或 owning skill。
- 更新後重新跑相應唯讀流程與 skill validator；不要寫入密碼、cookie、token、學生個資、目前任務結果或動態數值。
