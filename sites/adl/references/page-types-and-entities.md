# 頁型與資料模型

這份 reference 只描述可從 UI、操作手冊與 FAQ 推導的穩定結構；目前清單、數量、狀態、學生資料與排名不屬於模型。

## 公開頁型

### Home page

- 入口：`/HomePage/home/`。
- 作用：提供最新消息、活動、研習與帳號、操作手冊、FAQ、外部資源與頁尾導覽。
- 驗證：確認頁面標題／首頁內容，以及 header／footer 可見入口。

### News list

- 入口：首頁的「最新消息」／「檢視全部消息」。
- Entity：`NewsItem`，由當前 UI 提供日期、標題與 detail link；列表支援分頁。
- 驗證：確認 `最新消息` heading、當前頁碼與至少一筆日期／標題；點開時以 detail 頁再次確認。

### News detail

- 入口：從當前 News list 點擊某筆，而不是猜測 `Id`。
- Entity：`NewsItemDetail`，包含標題、更新時間、正文段落與可能的外部連結。
- 驗證：確認 detail heading、`更新時間`、正文與外連目的地；不要把正文的活動日期當成網站資料的新鮮度。

### Activity list

- 入口：首頁「更多活動」。
- Entity：`ActivityItem`，由日期區間、標題、活動／公告 detail 或外部目標組成；部分活動會導向不同網域。
- 驗證：確認 `更多活動` heading、日期區間與當前 item link；需要活動詳情時再開啟當前可見目標。

### First-party help/documentation

- 入口：`操作手冊`、`常見問題`、`網站導覽`。
- Entity：`HelpDocument` 或 `FAQEntry`；文件按角色／功能／格式分類，FAQ 按帳號、校管、教師、學習扶助、其他分類。
- 驗證：FAQ 篩選後要確認 active button 與 heading；手冊要確認對應角色或功能 heading，不以連結文字單獨推論文件內容。

### Account application

- 入口：`研習與帳號` → `帳號申請`。
- Entity：`AccountApplicationGuide`，按校管、教師、學生、家長、大學伴、展示帳號分 accordion，可能包含證明文件入口、線上表單與寄信要求。
- 驗證：確認當前 tab、角色 accordion 狀態與頁面內的申請說明；填寫、上傳、寄信或送出前停止。

## Teacher workspace entities

以下結構由初始登入教師儀表板的目前分頁視覺／DOM，以及公開 FAQ／操作手冊中的第一方流程共同支持；再次使用時仍要以當前登入狀態和 UI 為準。

### Task

- 目的：教師指派給班級／學生的學習內容或測驗。
- 重要欄位／狀態：任務類型、內容、名稱、開始／結束時間、對象、觀看與完成設定、完成率、教材完成率、觀看／測驗次數、節點狀態、答對率。
- 關聯：教師 → 班級／學生 → 任務 → 任務數據／診斷報告。
- 入口：儀表板 `+ 指派任務`／頂部 `指派任務`；進度從任務儀表板任務卡進入。

### Class and account

- 目的：教師或校管管理任教班級、學生帳號與班級歸屬。
- 重要欄位／狀態：學期、年級、班級、科目、身分、帳號狀態、教師／導師關係；實際值均為私人且動態。
- 關聯：學校／學期 → 班級 → 教師／學生 → 任務／學習資料。
- 入口：登入後的班級管理區塊；FAQ 使用 `帳號`、`帳號管理`、`科任班級設定` 等 label 描述。

### Learning-support assessment

- 目的：檢視科技化評量與學習扶助資料，並依領域／班級／學生挑選後續任務。
- 重要欄位／狀態：測驗、領域、班級類型、年級、班級、學生類型、節點、測驗模式、精熟／未精熟狀態。
- 關聯：學生帳號 ↔ 身分證／居留證後五碼綁定 ↔ 科技化評量結果 ↔ 學習扶助班級／任務。
- 入口：登入後「學習扶助」區塊 → `科技化評量` 或 `學習扶助編班`；所有目前名單與結果都需重新查詢。
