# 資料模型與識別方式

這份模型只描述 UI 中可觀察到的欄位、分層與連結關係。它不是網站內部資料庫 schema，也不授權 Agent 直接呼叫 API 或猜測 token。

## 入口與模組

```text
法學資料檢索系統
├── 法令判解系統
│   ├── 本院主管或審判相關法規（FLAW）
│   └── 判解函釋（FINT）
└── 裁判書系統（FJUD）
    ├── 裁判書查詢
    ├── 簡易案件查詢
    ├── 除權判決查詢
    └── 公示催告裁定查詢
```

## 法規資料（FLAW）

法規搜尋結果可按「法規名稱」與「條文內容」分組。結果項目可觀察到法規名稱、修正日期、原名稱、別名／顯示文字與英文入口；詳細頁可觀察到：

- 法規名稱、公布日期、修正日期。
- 「所有條文、編章節、條文檢索、條號查詢、修正條文、法規沿革」等同一法規的視圖。
- 條文層級的編、章、節、條號與全文。
- 友善列印、轉存 PDF、分享等動作入口。

已確認的路由家族包括 `/FLAW/dat02.aspx`、`dat03.aspx`、`dat04.aspx`、`dat05.aspx`、`dat07.aspx` 與 `dat01.aspx`；查詢結果中的完整 href 才是可靠來源。

## 判解函釋資料（FINT）

判解函釋結果會依資料態樣分組，UI 中已看到憲法法庭裁判、大法官解釋、大法官不受理決議、司法解釋、大法庭專區、停止適用之判例、精選裁判、決議、法律問題與行政函釋等分類。詳細頁可觀察到：

- 發文單位、解釋／裁判字號、日期。
- 標題、解釋爭點、解釋文與理由書／正文。
- 英文連結、友善列印、PDF、附件圖表與相關法條／相關法規。

FINT 詳細頁的路由形狀是 `/FINT/data.aspx`，常見參數包含資料識別、資料態樣、查詢 token、排序與輸出模式；所有參數都應從目前清單 href 取得。

## 裁判書資料（FJUD）

裁判書查詢結果以「查詢結果」為主，並提供依裁判法院、裁判案號年度、案件類別與裁判類別的側欄分類。清單欄位可觀察到：

- 裁判法院與裁判字號。
- 裁判日期與裁判案由。
- 正文摘要／內容大小提示。
- 分頁、排序與下一頁／最末頁控制。

裁判詳細頁可觀察到：

- 裁判字號、裁判日期、裁判案由。
- 主文、事實及理由與完整正文。
- 名詞查詢、名詞收集、友善列印、PDF 與分享入口。
- 歷審裁判清單，以及可延伸的同案詳細頁。

詳細頁路由形狀是 `/FJUD/data.aspx?ty=JD&id=<observed-id>&ot=in`。`id` 通常是複合識別字串，不能由顯示名稱或案件號自行拼接。

## 特殊程序資料

簡易案件、除權判決與公示催告裁定各自有一欄式／進階查詢入口，表單外觀相似，但應視為不同查詢資料集。除權判決和公示催告裁定的桌面入口透過 `defaultk.aspx?ty=E`／`?ty=V` 區分；不可因表單欄位相同而將結果混入一般裁判書查詢。

## 查詢結果與 iframe

法規、判解函釋與裁判書結果頁都曾觀察到 `iframe#iframe-data`。頂層頁面通常承載：

- 結果 heading、再檢索入口與側欄分類。
- 排序與篩選控制。
- iframe 內的清單、摘要、分頁與詳細結果連結。

查詢後先確認頂層 heading，再用 frame-scoped locator 讀取 iframe 內清單。若需要讀取詳細頁，先從 iframe 中取得目前可見 href，再在同一分頁開啟該 href；不要猜測或批量遍歷識別碼。

## 動態與時效

查詢 token、結果筆數、頁數、最新清單、瀏覽人次與查詢內容都可能變動。文件只保留欄位與路由形狀，不保留某次查詢的 token、筆數、熱門案件或最新日期。
